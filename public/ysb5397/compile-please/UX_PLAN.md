# 화면 구성·규정집 개선 회의

2026-11-14. 사용자 플레이 피드백을 바탕으로 아이온이 Gemini와 두 차례 논의하고 정정한 구현 전 권고안입니다. 회의 당시에는 구현 전 권고안이었으며, 이후 아래 고정 심사대·규정집 탐색·자동 방문자·해설 전환을 적용했습니다. 현재 동작과 실행 방법은 README.md를 참조하십시오.

회의: https://gemini.google.com/app/024b73f23bc3873c?hl=ko

## 사용자 피드백

1. 외형 작업실은 제거하고 무작위 방문자가 찾아오는 느낌만 유지합니다.
2. 1920×1080 화면 안에서 게임을 조작할 수 있도록 긴 페이지 스크롤을 없앱니다.
3. 긴 규정집을 읽고 탐색하는 방식을 재설계합니다.

## 권고 배치

전체 화면을 브라우저의 실제 가용 높이에 맞춘 고정 작업 공간으로 구성합니다. 1080px을 강제로 지정하지 않고 100dvh에 맞춰 영역을 배분합니다. 기존 올리브·차콜, 누런 종이, 녹색 규정집과 살구색 강조를 유지합니다.

```text
┌─────────────────────────────────────────────────────────┐
│ 진행 상황 · 주제 선택 · 코드 읽는 법                      │
├─────────────────────────┬───────────────────────────────┤
│ 작은 방문자 창구 + 주장  │ 규정집                        │
├─────────────────────────┤ 주제·조항 목차 │ 한 조항 본문   │
│ 제출 코드·자료          │ 기호 색인·검색·책갈피          │
│                         │                               │
├─────────────────────────┴───────────────────────────────┤
│ 자료 항목 ↔ 규정 조항 · 대조 · 증거 확인   반려 / 승인    │
└─────────────────────────────────────────────────────────┘
```

방문자 창구를 좌측 상단에 작게 배치해 코드와 규정에 공간을 배분합니다. 자동 외형은 근무 시드·신청자 ID로 정하고 같은 신청자의 외형은 새로고침·판정 전후에 유지합니다. 과거의 고정 외형 설정은 더 이상 적용하지 않습니다.

페이지 전체를 스크롤하여 도장을 찾지 않게 합니다. 긴 코드나 확대된 본문은 해당 영역 안에서만 스크롤합니다. 코드·규정 본문은 15~16px 이상의 읽기 쉬운 크기를 목표로 하며, 공간 확보를 위해 조건·예외를 자르지 않습니다. 작은 화면에서는 서류/규정 탭으로 전환할 수 있으나 대조·도장은 계속 화면 안에 남깁니다.

## 규정집 탐색

- 주제와 조항 제목 목록을 본문 옆에 함께 표시합니다. 목록·상세를 오가느라 반복해서 뒤로 이동하지 않게 합니다.
- 한 번에 한 조항을 보여 주고 이전/다음 조항으로 넘깁니다.
- 각 조항은 규칙·일반 예시·주의로 직접 편집합니다. 기존 설명과 적용 조건은 유지합니다.
- 기호 색인으로 ++, &&, ==, [] 등 코드에서 보이는 모양을 찾아 관련 조항 목록을 열 수 있게 합니다. 검색어를 모르는 초심자도 탐색할 수 있어야 합니다.
- 키워드 검색·직접 지정하는 책갈피·공통 코드 읽는 법을 제공합니다.
- 11개 주제와 모든 조항은 처음부터 열람할 수 있습니다. 현재 문제의 정답 조항을 자동으로 추천하거나 선택하지 않습니다.
- 기호·키워드가 같으면 현재 문제가 무엇인지와 관계없이 동일한 검색 결과를 제공합니다.

## 대조와 판정 후 복기

두 항목을 선택하면 대조하기만 활성화됩니다. 반려는 실제 모순 증거가 확정된 후 활성화합니다. 일치·비교 대상 아님은 반려를 열지 않습니다. 승인·반려는 플레이어가 내린 처분이며 정답·오답 표시와 구분합니다.

해설은 우측 규정집 자리에 표시하여 좌측 코드와 신청 내용을 계속 볼 수 있게 합니다. 규정집/해설을 자유롭게 전환하고 원래 보던 주제·조항·검색어·책갈피·스크롤 위치를 유지합니다. 확정 증거는 별도 버튼으로 다시 확인합니다. 대조·도장은 전환 중에도 같은 자리에 둡니다.

## 회의에서 정정한 제안

- 두 슬롯 선택만으로 반려 활성화 → 실제 모순 증거 확보 후 반려 활성화로 정정했습니다.
- 정수 나눗셈의 모호한 버림 표현 → 소수 부분을 0 방향으로 버린다는 설명으로 정정했습니다.
- 전체 화면을 가리는 해설 모달 → 코드가 남아 있는 우측 교체 패널로 보완했습니다.
- 첫 주제 자동 시작·추천 등급 배지 → 이번 변경에서 제외하고 주제 복수 선택을 유지합니다.
- 1920×900에 완벽히 들어간다는 표현 → 실제 측정 전 보장하지 않는 것으로 정정했습니다.
- 보기 좋게 맞추기 위한 설명 생략·강제 글자 축소 → 제외했습니다.

## 구현 후 검증할 사항

1. 1920×1080 및 1920×900에서 페이지 전체 스크롤이 없고 코드·주장·규정·대조·도장이 잘리지 않아야 합니다. 브라우저 UI와 화면 배율을 구분하여 실제 viewport를 측정합니다.
2. 1366×768과 글자 확대에서도 읽을 수 있어야 합니다. 필요한 경우 탭으로 전환하며 버튼이 화면 밖으로 밀려나지 않아야 합니다.
3. 가장 긴 코드·규정·신청 내용·해설과 이미지 실패 상태에서 내부 스크롤 및 대체 표시를 확인합니다.
4. 기호 색인·검색·조항 넘김·책갈피가 증거 선택과 구분되어 동작해야 합니다. 조항을 읽는 것만으로 증거를 확정하지 않습니다.
5. 해설/규정집 왕복과 새로고침에서 기존 근무·확정 증거가 유지되어야 합니다. 탐색 상태의 저장 범위를 명확히 정합니다.
6. 외형 작업실과 고정 외형 조작은 제거하되 무작위 부위 조합·중립 표정·몸 움직임·모션 감소를 유지합니다.

이 회의는 화면과 규정집 사용성에 관한 것입니다. 거부 사건·GC팀, 문제 추가, 무한 생성기 구현은 포함하지 않습니다.

## 적용 후 확인 결과

2026-11-14 로컬 Chrome에서 1920×1080, 1920×900, 1366×768, 390×844를 확인했습니다. 문서 전체 너비·높이가 각 viewport와 일치하며, 대조·승인·반려 버튼이 창 안에 있음을 DOM 실측으로 확인했습니다. 960×540에서도 내부 스크롤과 하단 조작을 확인했습니다. 실제 브라우저의 200% 확대 조작 자체를 재현한 것은 아닙니다.

1366×768에서 규정집의 접근 제어 조항을 아래로 읽은 뒤 해설/규정집을 왕복했을 때 스크롤 위치 291px와 책갈피가 유지되었습니다. 좁은 화면의 서류/규정집 탭 왕복에서도 같은 위치가 유지되었습니다. 출력 일치 시 반려 잠금, 모순 증거 확보 후 반려 활성화, 출근 전 읽기 전용 규정집도 확인했습니다. 프로젝트 자동 검사 26개가 통과했습니다.
