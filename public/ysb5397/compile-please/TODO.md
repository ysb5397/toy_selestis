# 코드 심사국 TODO — 최신 사용자 결정

기준일: 2026-11-14 (Asia/Seoul)

이 문서는 다음 구현을 위한 최신 결정과 미완료 작업입니다. 현재 소스에 이미 구현된 기능과 구분합니다. 과거 HANDOFF·SYSTEM_PLAN·UX_PLAN의 제안과 충돌할 때는 아래의 최신 사용자 결정을 우선합니다. 이번 업데이트는 기록·백업 작업이며 아래 기능을 새로 구현한 것은 아닙니다.

## 1. 반려·판정 오류 페널티·모순 증거의 역할 변경

- [ ] 모순을 발견하지 않아도 반려할 수 있도록 변경합니다.
- [ ] 잘못된 승인 또는 반려 등 판정 오류에 페널티를 부여합니다. 페널티의 종류·수치·누적 및 복구 방식은 아직 정하지 않았습니다.
- [ ] 사용자 결정: **모순 발견은 오로지 GC팀을 호출하기 위한 충분 조건입니다.** 모순 증거를 일반 반려의 필수 조건으로 사용하지 않습니다.
- [ ] 증거 없는 반려, 올바른 반려, 잘못된 반려, 증거 확보 후 GC팀 호출의 저장·복원·중복 입력 검사를 수정합니다.

현재 구현은 모순 증거가 있어야 반려 버튼과 판정 함수가 열리는 방식입니다. 따라서 이 항목은 기존 구현을 바꾸는 작업입니다. 현재 코드를 최신 정책의 완성본으로 해석하지 않습니다. 기존 회의의 ‘증거 제시·최종 안내·명시적 거부까지 모두 필수’라는 조건도 새 결정과의 관계를 다시 정리해야 하며, 별도 합의 없이 GC팀 호출의 추가 필수 조건으로 확정하지 않습니다.

## 2. 설정 모달

- [ ] 게임 안에서 열고 닫는 설정 모달을 추가합니다.
- [ ] 설정을 열어도 진행 중 서류·판정·증거가 손실되지 않도록 합니다.
- [ ] 음악·효과음의 켜기/끄기와 개별 음량, 모션 감소 등 필요한 항목을 정리합니다.
- [ ] 키보드 포커스, Escape 닫기, 배경 조작 방지와 설정 저장·복원을 처리합니다.

현재 ‘코드 읽는 법’·규정집 미리보기·증거 모달은 있으나 설정 모달은 없습니다.

## 3. 음악과 효과음

- [ ] 배경 음악과 효과음을 도입할 수 있도록 구조를 준비합니다.
- [ ] 음악과 효과음의 음량·음소거를 따로 제어하고 설정 모달과 연결합니다.
- [ ] 도장, 방문자 등장·퇴장, 서류 전환, 거부 행동과 GC팀 연출의 소리 위치를 설계합니다.
- [ ] 첫 사용자 조작 이후의 오디오 시작, 반복 재생, 탭 비활성화, 중복 재생 방지와 모션 감소를 함께 고려합니다.
- [ ] 사용 음원의 출처·이용 조건·원본과 적용 파일을 기록합니다.

현재 소리 토글과 판정 시 짧은 합성 톤은 있으나 배경 음악·실제 효과음 파일·독립 음량 설정은 없습니다. 음원이나 작곡 방향은 아직 확정하지 않았습니다.

## 4. 이미지 에셋 추가

- [ ] 방문자·거부 행동·GC팀·설정 및 규정집 조작에 필요한 추가 이미지를 정리하고 제작합니다.
- [ ] 기존 올리브·차콜, 누런 종이, 녹색 규정집과 살구색 강조의 시각적 일관성을 유지합니다.
- [ ] 타 게임의 디자인·캐릭터·화면 요소·에셋을 지나치게 동일하게 복제하지 않습니다.
- [ ] 투명 배경·표시 크기·접근 가능한 텍스트·이미지 실패 대체 표시를 검수하고 프롬프트와 사용처를 기록합니다.

기존 도장·낮 배경과 보존된 이미지 초안은 있습니다. 추가 에셋의 목록·제작 수량은 후속 작업입니다.

## 5. 단계 상승에 따른 검사 문법 확대와 문제 난도 재정의

- [ ] 단계가 올라갈수록 검사해야 하는 문법과 개념이 누적되거나 확장되도록 설계합니다.
- [ ] 사용자의 취지는 ‘규정은 간단하고 이해하기 쉬워야 한다’는 것입니다. 문제가 반드시 쉬운 단일 개념 예시에만 머물러야 한다는 제한으로 해석하지 않습니다.
- [ ] 규정의 표현은 간결하게 유지하면서 여러 규정을 함께 적용하는 더 어려운 문제도 구성할 수 있게 합니다.
- [ ] 문제 해결에 필요한 조건과 예외를 삭제하여 규정을 짧게 만들지는 않습니다.
- [ ] 단계 수, 단계별 문법, 해금·승급 조건, 복수 주제 선택과의 관계를 정리합니다. 이 세부 방식은 아직 확정하지 않았습니다.

현재는 11개 주제를 처음부터 복수 선택하는 구조이며 별도의 단계별 승급·해금 시스템은 없습니다. 사용자가 설명한 ‘단계 상승’의 구체적인 운영 방식은 다음 설계에서 재확인할 부분입니다. 과거 ‘모든 규정의 사전 공개’ 제안과 새 단계 구조의 관계도 자동으로 단정하지 않습니다.

## 6. 반려 후 제출자의 거부 행동과 GC팀

- [ ] 반려당한 제출자가 거부 행동을 보이는 사건 흐름을 추가합니다.
- [ ] GC팀 호출과 등장·동행 퇴장 등의 처리를 연결합니다.
- [ ] 1번의 새 정책에 맞춰 모순 증거와 호출 자격의 관계를 구현합니다. 증거 없는 반려도 가능하다는 점을 함께 반영합니다.
- [ ] 사건 시드·반응·호출·완료를 저장하여 재접속 때 재추첨되거나 중복 호출되지 않도록 합니다.
- [ ] 동작 중 다음 신청자 진입, 중복 입력, 모션 감소와 연출 종료 이벤트 누락을 처리합니다.

현재 거부 행동·GC팀은 구현되지 않았습니다. 구체적인 거부 반응과 GC팀 호출의 시점·표시 방식은 새 정책을 기준으로 설계합니다. 기존 회의안의 단계·타이머·점수 제안을 확정 사양으로 간주하지 않습니다.

## 7. 규정집 UI 추가 검토

- [ ] 현재의 주제/조항 목차, 한 조항의 규칙·일반 예시·주의, 기호 색인·검색·책갈피 구성이 실제 플레이에 적절한지 계속 검토합니다.
- [ ] 규정의 읽기 부담, 긴 조항의 내부 스크롤, 코드와 조항의 비교 동선, 선택 상태의 가시성을 개선합니다.
- [ ] 단계별 검사 문법이 늘어날 때 규정집의 범위와 탐색 방식을 함께 조정합니다.
- [ ] 한 화면의 심사대, 항상 보이는 대조·도장, 해설/규정집 왕복 시 읽던 위치 보존을 유지하며 가독성을 검증합니다.

현재 고정 심사대와 새 규정집 UI는 1차 적용된 상태이며 최종 확정된 사용성으로 취급하지 않습니다.
