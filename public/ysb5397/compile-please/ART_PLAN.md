# 코드 심사국 이미지 에셋 제안

2026-11-13, 아이온과 Gemini의 기획 대화 정리. 사용자 확정 전 제안이며 이미지 제작과 게임 코드 변경은 아직 진행하지 않았다.

대화: https://gemini.google.com/app/024b73f23bc3873c

## 방향

현재의 저채도 올리브·차콜, 누런 종이, 녹색 규정집, 살구색 강조를 유지한다. 원본 게임의 에셋을 복제하지 않고 코드 심사국의 오리지널 픽셀 그래픽으로 만든다.

승인·반려 도장은 **플레이어가 내린 처분**이다. **플레이어의 정답·오답**은 별도의 검토 전표로 표시한다. 정상적으로 실행되는 코드여도 신청자가 주장한 출력과 실제 출력이 다르면 반려 대상이다.

프레임은 애니메이션 전체 장수가 아니라 시트 내 각 그림 단위다. 표의 크기는 제작 목표이며 실제 제작물에서 검수한다.

### 도장 시안

- 승인: 짙은 청록 잉크(`#2E6F5E` 후보)의 이중 직사각형 안에 굵고 선명한 ‘승인’. 테두리 일부에 작은 잉크 빠짐을 넣되 한글 획의 판독을 해치지 않는다.
- 반려: 빛바랜 적갈색(`#A63A3A` 후보)의 사선 모서리 외곽선 안에 ‘반려’. 승인과 색상뿐 아니라 실루엣도 구분한다.
- 정답 피드백: 원형 체크가 붙은 ‘확인 완료’ 전표.
- 오답 피드백: 검토 아이콘이 붙은 ‘검토 필요’ 전표. 처벌이나 비난을 강조하지 않는다.

## 2차 후보

- 방문자 외형 추가, 짧은 표정 전환.
- 오답 재심사 서류에 붙는 포스트잇과 클립.
- 다음 신청자 전환 시 창구 셔터.
- 규정집 표지, 작은 기관 인장.

## 보류

- 종이 전체의 강한 노이즈 질감: 코드 가독성 저하 우려.
- 커피·스탠드·서류 소품 추가: 이미 배경에 있는 소품을 우선 유지하고 읽기 공간을 확보한다.
- 성적표 전용 배지: 노출 빈도가 낮아 도장·전표 재활용을 먼저 검토한다. 승인·반려를 성적의 좋고 나쁨으로 재해석하지 않는다.

## 제작 및 적용 원칙

- 픽셀의 기본 단위, 외곽선 두께, 명암 3단계를 통일한다. 기본 외곽선은 완전한 검정보다 짙은 차콜·올리브를 쓴다.
- 이미지 속 한글을 쓸 경우 ‘승인’과 ‘반려’ 두 글자의 오탈자·획을 직접 검수한다. 정확히 만들기 어려우면 도장 테두리 이미지와 실제 텍스트를 결합한다.
- 버튼 이름과 규정집 주제명은 HTML 텍스트로 유지한다. 이미지에는 적절한 대체 텍스트를 제공하고 중복 읽기를 피한다. 이미지 로드 실패 시 기존 텍스트 버튼·도장으로 복구한다.
- 코드, 실행 결과, 해설은 실제 텍스트로 유지한다. 도장은 미리 확보한 날인란에만 표시한다.
- 기본 2배 정수 확대와 `image-rendering: pixelated`를 사용한다. 임의 CSS 회전은 흐려질 수 있으므로, 기울어진 모양 자체를 원본 픽셀 격자에 그리는 방식이 우선이다.
- 나무 도구는 대기/눌림 2프레임과 짧은 이동을 조합하는 안을 우선 검토한다. 팔·손목 전체 이미지는 만들지 않는다. 모션 감소 설정도 반영한다.

## 아이온의 적용 전 보완 검토

Gemini의 제안을 그대로 구현하기 전에 다음을 조정한다.

- 128px 높이의 도장 도구는 64~72px 높이 모바일 고정 바에 그대로 들어가지 않는다. 모바일에서는 1배(48×64) 또는 별도 소형 구도를 사용하거나, 고정 바 대신 일반 문서 흐름의 버튼 영역을 쓴다.
- 하단 고정 바를 택한다면 바 높이와 safe-area만큼 본문 여백을 실제로 확보한다. ‘고정’만으로 본문 가림이 방지되는 것은 아니다.
- GPU 관련 CSS나 작은 회전 각도가 픽셀 선명도를 보장하지 않는다. 회전 없이 정수 좌표·배율을 기본으로 하고 실제 화면에서 확인한다.
- 방문자는 기존 도시 배경과 분리된 투명 레이어로 유지하는 편이 교체와 표정 변경에 유리하다.
- 탭은 아이콘과 주제명을 함께 표시한다. 모바일 규정집의 시트/탭 전환은 추가 UX 변경이므로 실제 필요를 확인한 뒤 적용한다.
