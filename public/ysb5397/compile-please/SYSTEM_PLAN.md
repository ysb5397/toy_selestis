## 1. 대조로 모순 확정 → 반려 → 거부 대응 → GC팀

### 사용자 설명에 따른 전제 수정

사용자가 의도한 것은 임의 반려에 정오답과 무관한 악성 사건을 붙이는 구조가 아니다. **제출 자료와 규정을 대조해 실제 모순을 확정하고 근거를 제시했는데도 제출자가 거부하는 상황**이다. 이전 회의의 ‘잘못 반려한 정상 신청자도 동일한 악성 사건을 일으킨다’는 전제는 폐기한다. 원작 게임의 모든 세부 규칙을 검증한 기록이 아니라 이번 프로젝트에 대한 사용자의 의도를 반영한 설계다.

### 대조 도구가 학습의 중심

구현 상태: 코드 행 또는 신청 결과와 규정 조항을 선택해 대조한다. 비교 가능한 조합만 실제 출력과 신청 결과를 검증하며, 관련 없는 조합은 결과를 누설하지 않는다. 확정된 모순 증거는 선택을 바꾸거나 새로고침해도 보관되고 반려 권한을 연다. 문제별 실제 출력은 JDK 21 실행 검증의 대상이다.

1. 코드의 특정 표현식·행, 신청자가 주장한 결과, 또는 규정집의 조항을 클릭한다.
2. 의미상 비교 가능한 두 항목을 선택해 대조한다. 문제별 비교 대상 ID와 적용 규칙 ID를 연결한다.
3. 결과는 ‘일치’, ‘모순 확정’, ‘비교 대상 아님’으로 구분한다. 엉뚱한 항목을 골랐다는 이유로 제출자를 위반자로 처리하지 않는다.
4. 실제 Java 규칙과 검증된 문제의 의미 모델로 모순을 확인한 경우에만 증거를 생성한다. 플레이어의 주장만으로 확정하지 않는다.
5. 증거에 비교 항목·규정·모순 원인과 실행 추적을 남긴 뒤 공식 반려·소명 단계로 진행한다.

예: 코드의 7 / 2와 정수 나눗셈 규정을 대조한다. 신청자가 출력 3.5를 주장했다면 실제 결과 3과의 모순을 확정할 수 있다. 학습 과제는 **어느 부분과 어떤 규칙이 충돌하는지 찾아 증명하기**로 확장된다.

이 사건 모드에서는 근거 없는 반려로 거부 사건이나 GC팀 호출을 열지 않는다. 제안은 모순 증거가 생긴 뒤 공식 반려를 활성화하는 방식이다. 기존 단순 판정 연습을 별도로 유지한다면 잘못된 반려는 학습 오판으로 처리하고 악성 민원 분기로 연결하지 않는다.

### 모순을 입증한 뒤의 반응과 대응

외형은 행동 성향과 무관하다. 무작위성은 이미 입증한 모순에 대한 반응·대사·몸동작에만 적용한다. 모순 자체나 증거의 타당성을 무작위로 바꾸지 않는다.

| 대응 단계 | 증거 제시 후 제출자 행동 | 사용자 대응 | 종료 |
| --- | --- | --- | --- |
| 0: 수긍 | 서류를 챙겨 수정하겠다고 함 | 별도 조작 불필요 | 짧은 퇴장 |
| 1: 이의 제기 | 설명이나 근거를 다시 요구함 | 확인한 모순 증거 제시 / 수정 사항 안내 | 수긍하면 퇴장 |
| 2: 거부·업무 방해 | 증거 확인 후에도 폭언하거나 버티며 절차를 거부함 | 공식 최종 퇴장 요청 / 처리 절차 경고 | 수긍하면 퇴장, 최종 요청도 거부하면 거부 확정 |
| 3: GC팀 처리 대상 | 모순 증거와 최종 안내 후에도 명시적으로 퇴장을 거부하거나 직접 위협함 | **GC팀 호출** | 팀 등장 → 양옆에서 동행해 화면 밖으로 데려감 |

최고 단계는 물리적 위험뿐 아니라 **입증된 모순에 대한 공식 처리·퇴장 요구를 끝까지 거부한 상태**도 포함한다. 사용자가 설명한 버티기도 GC팀 처리로 이어질 수 있다. 단순 질문이나 아직 근거를 보여주지 않은 항의는 이에 해당하지 않는다.

GC 버튼은 최고 처리 단계에서만 표시한다. ‘모순 증거 있음 + 증거 제시·공식 안내 완료 + 명시적인 거부/위협 확인’을 검사한다. 시간 경과나 숨은 확률만으로 최고 단계에 도달시키지 않는다. 직접 위협 사건도 모순 확정·증거 제시라는 선행 조건을 생략하지 않는다.

### 상태 흐름과 저장

코드·규정 클릭 → 대조 → 모순 확정 → 증거 기록 → 공식 반려·증거 제시 → 반응
- 수긍: 퇴장 후 상세 해설.
- 이의 제기: 증거 재제시·수정 안내.
- 거부·버티기: 최종 퇴장 안내.
- 거부 확정 또는 직접 위협: GC 버튼 표시 → 호출 → 팀 등장·동행 퇴장 → 상세 해설 → 다음 신청자.

기본은 무타이머다. 사건당 대응 결과를 한 번만 기록하고 반복 선택으로 보상을 얻지 못하게 한다. 학습 평가는 대조와 판정의 타당성으로, 대응 평가는 거부 이후의 절차 준수로 구분한다. 학습 전용에서는 증거 확인·반려 뒤 사건을 생략할 수 있다.

GC 호출은 한 번만 처리한다. 호출·이동 중 재호출과 다음 신청자를 잠그고, 모션 감소 설정과 연출 종료 이벤트 누락에 대한 완료 처리를 둔다.

저장할 내용: 문제 스냅샷, 비교 항목, 확정 증거와 규정 버전, 사건 ID·시드, 증거 제시·최종 안내 여부, 명시적 거부 여부, 현재 처리 단계, GC 호출 여부, 대응 결과. 재접속해도 증거와 사건을 다시 추첨하지 않는다.

## 2. 초급부터 고급까지 학습 과정

| 과정 | 주제 | 대표 심사 내용 |
| --- | --- | --- |
| 수습 / 초급 | 변수·자료형, 연산, 문자열 연결, 조건문·반복문 | 정수 나눗셈, 평가 순서, 반복 횟수 |
| 일반 / 초중급 | 배열, 메서드, String·StringBuilder, 참조 | 인덱스, 내용 비교, 참조 공유, 부분 출력 뒤 예외 |
| 선임 / 중급 | 클래스·생성자, 접근 제어, static, 상속·다형성 | 초기화, 오버로딩·오버라이딩, 메서드와 필드 구분 |
| 수석 / 중고급 | 제네릭, 컬렉션, equals/hashCode, 예외 처리 | 타입 제약, 순서가 정해진 연산, catch/finally, checked 예외 |
| 감사 / 고급 | 람다·Stream·Optional, record, sealed, 패턴 switch·record 패턴 | 지연 연산, 가변 객체 참조, 허용 상속 관계, 패턴 분해·매칭 |

현재 18문제를 전부 ‘초급’으로 취급하지 않는다. 배열 참조·객체·메서드 문제는 해당 과정으로 재분류한다. 기존의 여러 주제 선택 기능을 유지하고, 선택 범위는 해당 과정에서 배운 개념으로 제한할 수 있게 한다.

승급 기준은 아직 튜닝 전이다. 제안은 단계별 12건의 평가에서 10건 이상 정답을 맞히고 핵심 약점을 재심사하는 방식. 연습은 반복 가능하며 오답 한 번으로 누적 성과를 지우지 않는다. 해당 문제에 필요한 규정은 심사 전에 항상 열어볼 수 있어야 한다. 필요한 규정을 승급 뒤까지 감추지 않는다.

기준 버전은 JDK 21 LTS이며 Java 21 정식 기능만 기본 과정에 포함한다. switch 패턴 매칭과 record 패턴은 정식 기능이므로 고급 과정에 포함할 수 있다. String Templates, unnamed patterns/variables 등 Java 21에서 preview인 기능은 제외하며 --enable-preview는 사용하지 않는다. record를 다룰 때는 필드가 참조하는 가변 객체까지 자동으로 불변이 되는 것은 아님을 구분한다. 해시 컬렉션의 순회 순서, 스레드 실행 순서, fail-fast 예외 발생 타이밍처럼 안정된 정답을 제시하기 어려운 소재는 출력 판정에서 제외한다.

## 3. 고정 문제와 자동 생성: 혼합 방식 권장

| 방식 | 강점 | 한계 | 제안 |
| --- | --- | --- | --- |
| 직접 설계·검증한 고정 문제 | 교육 순서와 해설을 세밀하게 설계 | 문제 수가 한정됨, 검수 누락 가능 | 단계별 학습·평가의 기본 |
| 제한된 개념 템플릿 + 시드 | 정적 웹에서 계속 출제, 난도·재현 관리 가능 | 생성 규칙과 Java 모델의 오류 가능, 구조 반복 | **무한 모드의 첫 구현** |
| LLM 자유 생성 | 새로운 상황·구조 제안에 유용 | 정답·해설 검증 필요, 호출 비용·지연·운영 부담 | 우선은 개발용 문제 초안 생성에만 사용 |

전체 Java 프로그램을 무작위 조합하지 않는다. 검증 가능한 작은 문법 범위에서 의미 모델과 코드·해설을 함께 만든다. Java 코드를 JS eval로 실행하거나 Java와 JS의 연산 규칙이 같다고 가정하지 않는다.

### 첫 생성기: 6개 가족

정수 나눗셈 / 문자열 연결 / 단락 평가 / 조건 분기 / 유한 반복 / 1차원 배열.

각 가족은 수치뿐 아니라 연산 순서, 조건 방향, 반복 경계, 인덱스, 올바른 주장·오개념에 근거한 틀린 주장을 조합한다. 잘못된 주장으로 만든 값이 우연히 정답과 같으면 폐기·재추첨한다. 승인·반려 정답을 고정된 번갈아 순서로 내지 않는다.

초기 버전은 작은 정수와 제한된 반복을 사용한다. 입력뿐 아니라 중간 계산 결과도 허용 범위 안인지 검사한다. 임의 재귀, 파일·네트워크·시간, 무작위 실행 결과, 무한 반복, 오버플로, 실수 포맷 차이는 배제한다. 루프는 실제 반복 횟수의 상한을 보장해야 하며 단순히 N만 작다고 종료를 가정하지 않는다.

‘무한’은 출제를 계속한다는 의미다. 유한 템플릿에서 영구적으로 중복 없는 문제를 보장하지 않는다. 최근 출제 이력과 개념별 분포를 관리해 연속 중복과 한 주제 편중을 줄인다.

### 결과 데이터

실제 결과와 신청자의 주장을 동일한 구조로 비교한다.

```json
{
  "status": "NORMAL | COMPILE_ERROR | RUNTIME_EXCEPTION",
  "stdout": "정확한 표준 출력 문자열",
  "exceptionType": null
}
```

위 status의 세 문자열은 가능한 값 설명이며 실제 저장 시 하나만 사용한다. 런타임 예외 발생 전에도 stdout이 남을 수 있다. 빈 출력은 빈 문자열로 저장하고 UI에만 ‘출력 없음’으로 표시한다. 컴파일 오류에는 실제 실행 stdout이 없다. 스택 추적·컴파일러의 지역화된 메시지를 stdout에 섞지 않는다. 정상 종료는 exceptionType=null이며 예외 문제는 예외 클래스명을 별도로 비교한다.

문제마다 generatorVersion, templateId, seed, index, 난도, 학습 개념, 코드, 주장, 실제 결과, 실행 추적·해설을 기록한다. 재심사를 위해 생성된 문제 전체 스냅샷을 저장한다. 과거 문제를 새 생성기 버전으로 조용히 다시 생성하지 않는다.

### 검증 방식과 작은 실험 결과

템플릿의 의미 모델을 Java 21 규칙에 맞추고, 대표·경계·음수·예외 사례를 실제 `javac --release 21` 컴파일 및 `java` 실행과 대조한다. `--release`는 javac 옵션이다. 실행 도구를 만들면 표준 출력 인코딩과 환경을 고정한다. 검증 통과가 해설·난도·전체 조합의 무결성을 보장하지는 않는다.

이번 회의 중 작은 독립 실험에서 **6개 가족 × 3개 사례 = 18개**를 생성해 Java 21 대상으로 컴파일하고 실제 출력과 비교했으며 18개 모두 일치했다. 실험은 `outputs/java-generator-study/`에 있고 게임 런타임에는 포함하지 않았다. 이는 제한된 규칙 기반 생성이 가능하다는 근거이며 완성된 무한 모드나 전체 정확성 보장이 아니다.

장기적으로는 새 문제를 개발·빌드 단계에서 생성하고 격리된 JDK 환경에서 시간·메모리·출력량 제한을 두고 검증한 뒤 정적 문제은행으로 배포할 수 있다. 임의 사용자 코드 실행 서비스는 별도 과제다. LLM은 초안을 제안할 수 있지만 그 응답 자체를 정답 판정기로 사용하지 않는다.

## 4. 구현 순서 제안

1. 출력·컴파일 오류·런타임 예외의 결과 구조와 저장 버전부터 정리. 기존 18문제 동작을 유지하며 이관한다.
2. 클릭형 대조 도구와 모순 증거 기록부터 추가하고, 증거를 제시한 반려 뒤의 거부 대응·GC팀 호출·동행 퇴장을 연결한다.
3. 기존 문제를 재분류하고 초급→고급 과정 및 규정집을 확장한다. 처음에는 초급~중급의 내용부터 검증한다.
4. 6개 가족의 무한 모드를 열고 재현·오답 스냅샷·출제 분포를 연결한다. 고급 자동 생성은 검증 가능한 가족부터 점진적으로 추가한다.

## 회의에서 수정·보류한 안

- 2단계 경고 뒤 50% 확률로 최고 위험이 되는 안 → 제외. 관찰 가능한 행동과 규정 기반 전이로 보완.
- 기본 5~8초 타이머, 방치로 강제 종료 → 기본 모드에서는 제외.
- 고정 문제 100%, 생성기 99.9% 같은 수치 및 운영비 0원 보장 → 근거 없으므로 제외.
- 사용자 설명 반영: 임의 반려에 정오답과 무관한 악성 사건을 붙이는 안 → 폐기. 대조로 입증한 모순과 증거 제시 이후의 거부만 대상으로 한다.
- LLM 실시간 자유 생성과 무검증 즉시 출제 → 첫 구현에서는 제외.
